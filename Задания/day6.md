# Day 6

## Класс — это способ сказать: "вот эти данные и вот эти действия над ними логически принадлежат одной сущности, давай упакуем их вместе".

Это называется инкапсуляция — один из фундаментальных принципов ООП (объектно-ориентированного программирования). Вместо "данные отдельно, функции отдельно" получаем "данные + функции над этими данными — единое целое".

## Класс vs объект — ключевое различие

Это первое, что нужно чётко разделить в голове:

Класс — это чертёж, шаблон, описание того, какие данные и поведение будут у сущности. Класса самого по себе "в памяти как что-то конкретное" не существует — это описание.
Объект (он же экземпляр, instance) — это конкретная вещь, созданная по этому чертежу, с конкретными значениями.

Аналогия: класс Car — это чертёж автомобиля вообще (у машины есть цвет, марка, объём бака, она умеет ехать и тормозить). Объект — это конкретная машина у тебя во дворе: красная Toyota с определённым объёмом бака. Из одного чертежа можно "напечатать" сколько угодно разных объектов — и каждый будет иметь свои собственные значения полей, независимые от других.

Применительно к твоей игре: класс Enemy — это чертёж "что вообще такое противник" (здоровье, сила, ловкость, враждебность + умение атаковать). А конкретный зомби на уровне 3 и конкретный вампир на уровне 5 — это два разных объекта, созданных из класса Enemy (точнее, из его "потомков" — но до наследования мы ещё не дошли, на очереди).

## Атрибуты и методы

У объекта есть два вида "содержимого":

Атрибуты (attributes) — это данные, состояние объекта. Для машины: цвет, скорость, объём бака.
Методы (methods) — это действия, которые объект умеет выполнять. Для машины: ехать, тормозить, заправиться. По сути метод — это обычная функция, но "живущая внутри" класса и имеющая доступ к атрибутам этого конкретного объекта без необходимости передавать их параметрами.

Это прямой ответ на боль из прошлого занятия: методу attack() внутри класса Character не нужно принимать health и strength параметрами — он и так "знает", у какого конкретно персонажа его вызвали, и может напрямую читать/менять его атрибуты.

##  такое self

Вот это обычно самый непонятный момент для новичков, разберём подробно.

Когда ты пишешь метод внутри класса, первым параметром всегда идёт специальный параметр, который по договорённости называют self. Он означает: "этот конкретный объект, у которого сейчас вызывается метод".

Смысл в следующем: у тебя может быть создано 10 разных объектов-врагов из одного класса Enemy. Когда ты вызываешь метод attack() у третьего врага, откуда методу знать, чьё именно здоровье уменьшать — первого, третьего или пятого? Ответ: через self — Python автоматически передаёт туда ссылку на тот самый объект, у которого метод был вызван. Внутри метода self.health означает "здоровье именно этого объекта", а не какого-то абстрактного здоровья вообще.

Схематично (не про твою игру, просто структура):

класс Животное:
    метод издать_звук(self):
        напечатать(self.имя, "издаёт звук")

животное1 = Животное(имя="Кот")
животное2 = Животное(имя="Собака")

животное1.издать_звук()   # напечатает "Кот издаёт звук"
животное2.издать_звук()   # напечатает "Собака издаёт звук"

Хотя метод издать_звук определён один раз, при вызове через животное1.издать_звук() внутри метода self автоматически "указывает" на животное1, а при вызове через животное2.издать_звук() — на животное2. Ты не передаёшь self вручную — Python подставляет его сам, когда видишь запись объект.метод().

Конструктор — метод __init__

Когда объект создаётся, обычно сразу нужно задать ему начальные значения атрибутов. Для этого есть специальный метод с зарезервированным именем __init__ (двойное подчёркивание с двух сторон — такие методы в Python называются "магическими" или "дандер"-методами, dunder = double underscore; __init__ — самый частый из них).

__init__ вызывается автоматически в момент создания объекта — тебе никогда не нужно вызывать его руками.

### Схематичный пример структуры (снова абстрактный, не игровой):

класс Животное:
    метод __init__(self, имя, возраст):
        self.имя = имя
        self.возраст = возраст

животное1 = Животное("Кот", 3)

Что здесь произошло по шагам:

Питон видит Животное("Кот", 3) — команду создать новый объект.
Автоматически создаётся "пустой" объект и передаётся в __init__ как self.
"Кот" и 3 передаются как имя и возраст.
Внутри __init__ строчки self.имя = имя и self.возраст = возраст записывают переданные значения как атрибуты именно этого объекта.
Готовый, полностью проинициализированный объект возвращается и сохраняется в переменную животное1.

Важно понимать разницу между имя (параметр, временная переменная, живущая только пока выполняется __init__) и self.имя (атрибут, который останется с объектом навсегда, пока объект существует).

Разные объекты — разные данные, общий код

Ключевая идея, ради которой всё это затевается: код метода один, а данные — свои у каждого объекта. Это устраняет ровно ту проблему, которая у тебя была: раньше enemyHealth было одно на всю программу, и если бы у тебя было два врага одновременно, ты бы не знал, как хранить два разных здоровья без каши из enemyHealth1, enemyHealth2. С классом это решается само — просто создаёшь два объекта, у каждого свой независимый self.health.

Небольшая терминологическая база напоследок
Класс — чертёж/шаблон.
Объект / экземпляр — конкретная реализация по чертежу.
Атрибут — данные объекта (self.что-то).
Метод — функция, принадлежащая классу, действие над данными объекта.
self — ссылка на текущий объект внутри метода, подставляется автоматически.
__init__ — специальный метод-конструктор, вызывается при создании объекта, задаёт начальные значения атрибутов.
Инкапсуляция — принцип "данные и поведение над ними — вместе, в одной сущности", а не разбросаны глобальными переменными и функциями отдельно.

## Тема: наследование

Это второй фундаментальный столп ООП (после инкапсуляции), и он напрямую нужен для задания — там 5 видов врагов с общими характеристиками (здоровье, ловкость, сила, враждебность), но с разным поведением.

Проблема, которую решает наследование

Представь, что тебе нужны классы Кошка и Собака. У обоих есть имя, голод, метод покормить() — код будет дублироваться между классами почти один в один. Дублирование кода — это плохо: если завтра ты решишь поменять логику кормления, придётся чинить её в двух (или пяти) местах, и легко где-то забыть.

Наследование позволяет описать общую часть один раз в базовом (родительском) классе, а затем создать дочерние (наследующие) классы, которые автоматически получают всё содержимое родителя и могут:

использовать его как есть,
добавлять новые атрибуты/методы,
переопределять (изменять) поведение конкретных методов под себя.
Синтаксис
класс Родитель:
    def __init__(self, параметр1):
        self.параметр1 = параметр1
    def метод_А(self):
        ...

класс Потомок(Родитель):
    pass    # пока ничего не меняем — Потомок получает всё от Родителя автоматически

Запись класс Потомок(Родитель): — вот это и есть наследование: в скобках после имени класса указывается, от кого наследуемся. Потомок теперь имеет доступ ко всем атрибутам и методам Родитель, как будто они были написаны прямо внутри него.

## Переопределение метода

Если в дочернем классе определить метод с тем же именем, что у родителя — он "перекроет" родительский, когда вызывается у объекта дочернего класса:

класс Родитель:
    def издать_звук(self):
        print("Родитель издаёт какой-то звук")

класс Потомок(Родитель):
    def издать_звук(self):
        print("Потомок издаёт СВОЙ звук")

а = Родитель()
б = Потомок()
а.издать_звук()   # "Родитель издаёт какой-то звук"
б.издать_звук()   # "Потомок издаёт СВОЙ звук" — сработал метод потомка, не родителя

Это называется полиморфизм — способность объектов разных классов реагировать по-разному на один и тот же вызов метода. Применительно к твоему заданию: у тебя будет базовый Enemy с общим методом move(), а Zombie, Vampire, Ogre и т.д. переопределят move() каждый под свой паттерн передвижения — и вызывающему коду не придётся знать, какой конкретно тип врага перед ним, он просто вызовет enemy.move(), а нужная версия метода сработает сама.

super() — вызов метода родителя изнутри потомка

Часто нужно не полностью заменить поведение родителя, а дополнить его. Для этого есть super() — способ явно вызвать версию метода из родительского класса, находясь внутри переопределённого метода потомка.

Самый частый случай — __init__ потомка, который добавляет новый атрибут, но не хочет дублировать код инициализации общих атрибутов:

класс Родитель:
    def __init__(self, имя):
        self.имя = имя

класс Потомок(Родитель):
    def __init__(self, имя, дополнительный_параметр):
        super().__init__(имя)              # вызвали __init__ родителя, он настроил self.имя
        self.дополнительный_параметр = дополнительный_параметр   # добавили своё

Без super().__init__(имя) тебе пришлось бы писать self.имя = имя заново внутри Потомок — дублирование, которого мы и пытаемся избежать.

Как это ляжет на задание

Смотри на структуру, которая у тебя получится (это план, не код для копирования):

Базовый класс Enemy — общие атрибуты (health, agility, strength, aggression) и, возможно, общий метод attack().
Zombie(Enemy), Vampire(Enemy), Ghost(Enemy), Ogre(Enemy), Snake(Enemy) — каждый наследует общее, но переопределяет move() под свой паттерн, а некоторые ещё и attack() (например, у Вампира особая механика — первый удар всегда промах, у Огра — контратака после отдыха).


## Задание

Напиши иерархию классов (полностью с нуля, без подглядывания в старые файлы):

Базовый класс Animal:
__init__(self, name, health) — сохраняет оба атрибута.
Метод make_sound(self) — печатает f"{self.name} издаёт звук".
Метод info(self) — печатает f"{self.name}, здоровье: {self.health}".
Класс Dog(Animal):
Переопредели make_sound — печатает f"{self.name} лает: Гав!".
Не трогай __init__ вообще (пусть используется родительский как есть).
Класс Cat(Animal):
Свой __init__(self, name, health, is_lazy) — принимает дополнительный параметр is_lazy, вызывает super().__init__(...) для name и health, и дополнительно сохраняет self.is_lazy.
Переопредели make_sound — если self.is_lazy == True, печатает f"{self.name} слишком ленив, чтобы мяукать", иначе f"{self.name} мяукает: Мяу!".
Снаружи классов: создай одного Dog и двух Cat (один ленивый, один нет), вызови у всех троих make_sound() и info().
